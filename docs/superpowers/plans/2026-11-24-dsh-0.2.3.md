# DSH 0.2.3 兼容线记录（2026-11-24）

## 结论

DSH `0.2.3-alpha.2` 对插件只有一个硬断点：Connection 的 `requestRejection` 被删除，WebServer 改为
路由级 `auth`（默认 `required`）并在 handler 第三个参数传入已认证的 `peer`。插件设置页的预览路由
（`src/preview.ts`）原来直接调用 `connection.requestRejection(req)`，在 0.2.3 上会抛
`TypeError`，被 WebServer 兜底成 **400**，于是设置页的预览永远不可用。

其余缝在 0.2.3 上可用：`dsh-fs-sandbox` 与 `dsh-sandbox-local` 的 `src` 未变；
`additionalWritableRoots`、`confine`、`internal/get`、settings 的 volatile `Config`、客户端
`settings.section` / `plugins.row.config` / `configForms` 都保持原契约。

## 逐项 diff 结论

| 检查项 | 0.2.3-alpha.2 | 处理 |
|---|---|---|
| `dsh-client-connection` | `requestRejection` 删除；新增 `webserver/authorize` 监听 | 预览路由改为可选调用 + 显式 `auth: 'required'` |
| `dsh-host-webserver` | `WebRoute.auth` 默认 `required`；handler 收 `peer` | 旧线忽略该字段，继续由 Connection 拒绝未认证请求 |
| `dsh-sandbox-policy` | workspace root 改为 `workingDirectory.get(session) ?? header.cwd` | prompt 与 tool guard 同样优先使用该服务 |
| `dsh-fs-sandbox` / `dsh-sandbox-local` | `src` 未变 | 不修改包装器 |
| `dsh-settings` | 仅 cordis root 访问方式变化 | volatile Config 路径不变 |
| `dsh-system-prompt` | 新增 admission/projection；`context()` / `getContextOrder()` 保留 | 动态 context 可继续使用；补 `interpolate: false` 硬化 |
| cordis | `ctx.root` → `ctx[Context.root]`；intercept config → metadata | 插件未使用这些符号 |
| 客户端 slots / manifest | `settings.section`、`plugins.row.config`、`configForms`、`dsh.client.inject` 未变 | 不修改 |

0.2.3 里 `settings.plugin.item` 已不存在，但它在 0.2.x 中本来就是 inert；插件对它的注册继续保留给 0.1.5。

## 实测（scratch DSH_HOME，非用户配置）

环境：npm 上的 `@deepseek-ai/dsh@0.2.3-alpha.2`，临时 `DSH_HOME=/tmp/dsh-home-023`，
web/headless profile 用 `link:` 安装本仓库；另用 `0.2.2-rc.5` 做旧线回归。

| 场景 | 结果 |
|---|---|
| 0.2.3 + 未修 preview + 已认证 cookie | `400 Bad Request` |
| 0.2.3 + 修复后 + 已认证 owner | `200`，返回 workspace/platform/capabilities JSON |
| 0.2.3 + 修复后 + 无 cookie | `401`（WebServer 默认 auth） |
| 0.2.3 + 修复后 + 非 owner peer | `403` |
| 0.2.2 + 同一份修复 + cookie / 无 cookie | `200` / `401`（旧 Connection fence 仍生效） |
| 0.2.3 插件启动 | 插件行激活；没有 `internal/get` 自检告警；web boot 表包含 `dsh-extra-paths/client.js` |
| 0.2.3 工作区外写探针（配置额外根） | 文件出现 |
| 0.2.3 同一探针（不配置额外根） | 文件未出现 |
| 0.2.3 类型检查 | `tsc -p tsconfig.json` / `tsc -p tsconfig.client.json` 通过 |

说明：shell 侧仍受"本会话内嵌套 `sandbox-exec` 不可用"限制，沿用 `tests/argv.test.ts` 的真实 provider
argv 夹具，不在 scratch 环境重复验证。

### 浏览器 UI（Chrome DevTools Protocol）

同一 scratch web profile 在 headless Chrome 中完成一次真实交互：

1. 用 token 登录后打开 **设置**，左栏出现插件注册的 **额外可写路径**（settings.section）。
2. 基线工作区填 /tmp，规则文本填 /tmp/dsh-ui-probe | write | fs；展开「解析预览」显示 **生效根 1 条**，
   行内为 /tmp/dsh-ui-probe → /private/tmp/dsh-ui-probe（macOS 的 /tmp 规范化），说明 preview 路由被真实调用。
3. 点 **保存** 后按钮变为「已与配置同步」；刷新页面重新打开该页，规则仍然存在。
4. 插件页中 dsh-extra-paths 显示 **v0.4.0**；该行「配置」打开同一个页面，并读到刚保存的规则。
5. 浏览器 performance resource 中出现 /extra-paths/resolved，返回 200；无 cookie 的 HTTP 请求仍是 401。

同一流程也在 Safari 原生窗口用 computer use 重跑了一遍：AX 定位「账号菜单 → 设置 → 额外可写路径」，
点击基线输入框与规则文本域后用键盘输入，预览显示「生效根 1 条」，点击保存变为「已与配置同步」；
Cmd+R 刷新后重新进入该页，规则文本仍在。两条路径（CDP 与 CUA）得到一致结果。

结论：0.2.3 的 Web 设置页、插件行配置入口与 preview 路由均可正常使用。

## 实现

- `src/preview.ts`：`requestRejection?` 可选调用；路由显式 `auth: 'required'`；handler 第三参
  `peer.principal.kind === 'owner'` 限制预览读取 host 路径。
- `src/session-dir.ts`：新增结构性 `sessionDirectoryOf(ctx, session)`，feature-detect
  `ctx.get('workingDirectory')`，任何异常/空值都回落。
- `src/index.ts`：prompt context 与 tool guard 使用该 helper；context 增加 `interpolate: false`。
- `src/tool-guard.ts`：`ToolGuardDeps.sessionDir?`，优先于 header cwd。
- 版本 `0.4.0`；CI/release 的 peer 锚点改为 `0.2.3-alpha.2`；README/AGENTS 同步。
