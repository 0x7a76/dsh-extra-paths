# dsh-extra-paths

[English](README.md) | 中文

让 DSH 对一组配置的外部路径**首次尝试即可写、无需审批**：既覆盖 `write`/`edit` 工具，也覆盖 `bash` 子进程。
0.3.0 起每条路径还带**访问级别**：`deny`（禁止读写）、`read`（只读）、`write`、`always-write`；路径可以按
Windows、macOS/Linux 或 WSL 的写法书写，因此同一份配置能跨机器共用。插件以服务包装实现，不改 DSH 核心代码，
并提供 Web 设置页与「当前工作区解析出的生效规则」实时预览。

## 安装

需要 DSH `0.1.5` / `0.2.0` / `0.2.1` / `0.2.2`（不在范围内会被安装闸门拒绝）。

```bash
dsh plugin --profile <name> add dsh-extra-paths            # <name>=你的 profile 名
```

想从源码安装（开发时）：

```bash
pnpm install && pnpm build
dsh plugin --profile <name> add /path/to/dsh-extra-paths   # 路径=本仓库的绝对路径
```

装好后打开设置左栏的「额外可写路径」。在 **设置 → 插件** 里，同一页在这个插件自己那一行上：
打开 `dsh-extra-paths` 组合包，点该行的「配置」。

页面文案跟随 DSH 自己的语言选择（**设置 → 常规 → 语言**）：内置简体中文与英文两套文案，
其它界面语言回落到英文。

## 访问级别

每条路径有一个访问级别和一组**作用面**。`deny` 与 `read` 是 0.3.0 新增的——在此之前每条都只是写授权
（`write` / `always-write`，当时写作 `scope`）。

| `access` | fs 工具：读 | fs 工具：写 | bash：读 | bash：写 |
|---|---|---|---|---|
| `deny` | 拒绝 | 拒绝 | 拒绝¹ | 拒绝¹ |
| `read` | 允许 | 拒绝（即使在工作区内） | 允许 | 拒绝¹ |
| `write`（默认） | 允许 | 会话为 `workspace-write` 时允许 | 允许 | `workspace-write` 时允许² |
| `always-write` | 允许 | `read-only` 会话也允许 | 允许 | `read-only` 会话也允许² |

¹ 仅当 shell 沙箱能**扣减**权限时可保证：macOS seatbelt 与 Linux bwrap。Linux landlock（没有 bwrap 时的后备，
含未装 bwrap 的 WSL）与 Windows ACL 上 bash 不遵守 `deny`/`read`，但 fs 工具仍然执行——见
[已知边界](#已知边界)。² 宿主无法在 Windows 上表达额外的 bash 授权；fs 工具侧照常授权。

- **最严规则胜出**：对同一目标，`deny` > `read` > `write`/`always-write`。覆盖同一目标的更宽可写规则**不会**放大
  `read`/`deny` 规则（可写根里被 deny 的子目录依然被拒）。`write` 与 `always-write` 合并取 `always-write`；访问级别
  按**作用面**分别结算——同一个根可以「fs 工具可写、bash 只读」。
- **`deny` 是硬规则**：拒绝内容读取（`read` 工具、图片/字节读取、目录列举与 `watch`）与所有写入；`deny` 与
  `read` 在 `danger-full-access` 下对 fs 工具照样生效（该模式没有 shell 沙箱层，因此 bash 不受这条规则约束）。
- **`read` 只降级写入、保留读取**：适合工作区内需要保持写保护（只读）的目录（`.git`、`node_modules`、构建产物）。
- **作用面**（默认 `[fs, shell]`）：`fs` = fs 工具——读取/列举，以及 `write`/`edit`、apply-patch 与删除/移动操作；
  `shell` = `bash` 子进程。规则只在列出的表面上生效，所以只在 `fs` 上的 `deny` 不会阻止 bash 读该路径（反之亦然）。
- 读的**元数据**（`stat`/`lstat`/`resolve`）不拦截，只拦内容访问——见「已知边界」。

## 配置

写进设置文档 `~/.dsh/settings.yaml` 的 `extra-paths` 段，或直接用设置页（**保存即生效，无需重启**）。
下面的 `<工作根>` 是占位符，指你放项目的那个上层目录（绝对路径，或 `~/` 开头的路径）：

```yaml
extra-paths:
  defaultAccess: write                         # 条目省略 access 时的默认级别（默认 write）
  defaultSurfaces: [fs, shell]                 # 默认作用面（默认 fs + shell）
  paths:
    - <工作根>/notes/home                      # 裸字符串 = 用默认访问级别/作用面
    - path: ../../notes/home                   # 相对路径按「会话工作区」解析
      access: always-write
    - path: <工作根>/some-repo
      access: write
      surfaces: [fs]                           # 只作用于 fs 工具：bash 既不放行也不限制
    - path: ~/.ssh
      access: deny                             # 拒绝读写（平台支持时 bash 也拒）
```

访问级别为 `deny` / `read` / `write` / `always-write`；作用面为 `fs` / `shell`。裸字符串条目继承 `defaultAccess`
与 `defaultSurfaces`；对象条目省略其中任一字段时也继承对应默认值。

### 从 0.2.x 迁移

旧写法继续被接受：条目上的 `scope: write|always-write` 映射到同名的 `access`，`defaultScope` 是 `defaultAccess`
的旧别名。配置无需改动。若同一条目同时写了 `scope` 与 `access` 且值不一致，保存会被拒绝，而不是悄悄取其中一个。

**一处有意的语义变化**：不含 `/` 的写法（`notes`、`secrets`、`.git`）以前指 `<工作区>/<名字>`，现在表示
[名称规则](#名称规则裸名一个名称任意深度匹配)（该名字在任意深度匹配）。要保留原来的字面含义请写 `./notes`。

### 相对路径怎么写

相对路径按**各会话自己的工作区**解析（设置页里可以改「基准工作区」来预览）；**不含分隔符**的写法是名称规则，见
[名称规则（裸名）](#名称规则裸名一个名称任意深度匹配)：

| 写法 | 解析成 | 说明 |
|---|---|---|
| `..` | `<工作根>` | 工作区的**上一层**，该目录及其所有兄弟目录都可写 |
| `../某仓库` | `<工作根>/某仓库` | 只放行那一个兄弟仓库（比 `..` 精确，推荐） |
| `../../notes/home` | `<工作根>/notes/home` | 往上几层再进别的树 |
| `~/notes/home` | 家目录下 | 与工作区无关；`~user` 不展开（与宿主一致） |

### 名称规则（裸名）：一个名称，任意深度匹配

`path` 里**不含分隔符**时（`.git`、`.env`、`node_modules`）是**名称规则**而不是路径：匹配「会话工作区 + 所有配置的
可写根」内**任意深度**的同名组件（文件或目录），并覆盖每个匹配的整棵子树。一行配置就能保护每个仓库里的同一种结构，
既不用逐仓库写路径，也不用"遍历全盘"的模式：

```yaml
paths:
  - path: .git
    access: deny            # 无论在哪个仓库，都拒绝仓库元数据
    surfaces: [fs]          # 名称规则只作用于 fs 工具（见下）
  - path: .env
    access: deny            # 作用范围内任意位置的密钥文件
  - path: node_modules
    access: read            # 依赖目录：可读、不可写
```

- **作用范围**：只从会话工作区与已配置的可写根（预览里列出的作用根）开始匹配，不会遍历整个磁盘。
- **逃生写法**：`./notes` 带分隔符，仍是字面量的工作区相对路径；当某个单段名称必须表示"工作区下的这个目录"而不是
  「任意深度」时用它。
- **四种访问级别都合法**，但推荐 `deny` / `read`：名称级别的授权（`write` / `always-write`）会把作用范围内所有同名
  目录一起授权。
- **只作用于 fs 工具——这是有意的。** 名称规则在每次 fs 调用时按路径段词法匹配：精确、实时（刚创建的目录立刻
  生效）、零目录遍历。shell 面无法表达"名称"，而"按命令枚举当前匹配"的实现在真机上被证明代价高、最多滞后 30 秒、
  且某个可写根很深/不可读时只能部分覆盖——所以**不做**：名称规则**不约束 bash**。要让 shell 也受约束，请写具体
  路径或 `*` 模式（两者在 fs/shell 两侧都精确）。名称规则即使写了 `shell` 作用面，宿主也只会告警一次：fs 工具
  照常保护，bash 不受约束。
- **要让 bash 也受约束？用模式。** 含 `*` 的写法是模式（永远不会被当作名称规则），而模式正是 shell 面唯一能表达
  的形式：以通配符开头的模式锚定在**会话工作区**，所以 `**/.git` 不用写死本机工作根就能保护其下每个仓库的
  `.git`；最后一段是字面量时还能匹配**文件**（`**/.env`）。见下节。

### 模式：按路径结构锚定（不用写死路径）

`path` 里可以用通配符描述**一组路径**（目录，或最后一段为字面量时的文件），于是"路径里存在某个结构"可以变成一个条件：

| 写法 | 命中（授予的根） |
|---|---|
| `<工作根>/**/.worktrees/..` | 每个**含 `.worktrees` 的仓库根**（`.worktrees` 的上级） |
| `<工作根>/**/.worktrees/*` | 每个具体 worktree（不碰 `.git` 与主检出） |
| `<工作根>/<某仓库>/.worktrees/*` | 某一个仓库下所有 worktree（**零遍历开销**，最推荐） |
| `<工作根>/*/notes` | 每个仓库/项目下的 `notes` 目录 |
| `**/.git` | **会话工作区**下每个 `.git` 目录（受深度上限约束） |
| `**/.env` | 会话工作区下每个 `.env` **文件** |
| `<工作根>/**/.git` | 同上，但锚定在绝对工作根，所有会话共用 |

语法：`*` = 恰好一层、`**` = 最多 3 层（**只匹配真实存在的路径**，所以"必须存在 `.worktrees`"是自然结果）；
**最后一段是字面量时也会匹配文件**（`**/.env`）；结尾的 `..` 在**命中之后**再上移（因此 `…/.worktrees/..` 就是
"`.worktrees` 的上级"，不会被词法折叠吃掉）。

**锚点**：可以是绝对路径（`~`、`/…`、`C:\…`），也可以是**工作区相对**——以通配符开头（`**/.git`、`*/src`）或
带字面量前缀（`services/**/notes`、`../**/.git`）的模式锚定在**会话工作区**，与相对路径一致，因此同一份配置在
每个检出里都能用、无需写死本机工作根。带 `\` 分隔符的 Windows 写法会按它自己的方言解析；锚点属于另一种平台的
模式变为 inactive（`foreign`）并给出告警，而不是保存失败。

安全边界（都是硬约束，不是建议）：

- **绝对 / `~` 锚点**至少两层字面量且不能是卷根 —— `/**`、`~/**`、`/srv/**` 一律拒绝；**工作区相对锚点**至少要
  有一个字面量段，`**` / `**/*` 这种"扫全工作区"的纯通配一律拒绝
- 遍历**不进入** `node_modules`、`.git`，`**` 也不进入隐藏目录——但**最后一段字面量可以命中 `.git` 本身**
  （`**/.git` 就是这么工作的），只是永远不会看进它内部
- 有界：`**` 最多 3 层、目录数 > 4096 或命中 > 256 时**整个模式不生效**（fail closed，绝不给"部分命中"这种不可预期的授权）；触顶原因会写进告警
- 展开结果缓存 30 秒，因此**新建的 worktree/`.git` 最迟 30 秒**被纳入
- 模式也是 **shell 面**能表达的形式：macOS seatbelt 与 Linux bwrap 上会把命中路径注入沙箱（有界 + 缓存）；
  landlock 与 Windows ACL 仍然无法扣减

解析预览会显示宿主对**每一条配置的答案**：解析到的绝对路径（符号链接以宿主规范化后的结果为准）、状态徽标
（`[生效]`、`[缺失]`、`[已拒绝]`、`[当前平台不适用]`），以及模式/名称规则当前的命中数。0 命中、被拦截、
平台不匹配的条目都会明确说明，所以不必"先保存再看解析对不对"。

## Windows、WSL 与 macOS/Linux：一份配置到处可用

配置里的路径可以按任意平台的写法书写；由**宿主**解析，并在可以映射时做 Windows ⇄ WSL 互译，然后拿真实文件系统
校验。页面只显示宿主的答案——浏览器从不自己猜平台（WSL 下浏览器是 Windows Chrome 而宿主是 Linux，远程 Web
客户端更是另一台机器）。

| 写法 | 含义 |
|---|---|
| `C:\work\shared`、`C:/work/shared` | Windows 盘符路径，两种分隔符都接受 |
| `\\server\share\docs` | Windows UNC 共享 |
| `C:foo` | 保存时拒绝（盘符相对路径，取决于该盘的当前目录） |
| `/mnt/c/work` | `C:\work` 的 WSL 写法（挂载根从挂载表探测，缺省 `/mnt`） |
| `/c/work` | `C:\work` 的 git-bash/MSYS 写法；仅当宿主机上该盘存在时可用（否则为 `missing`） |
| `~/projects`、`~\projects` | 家目录；两种分隔符都接受 |

- **WSL ⇄ Windows 互译**：WSL 里 Windows 盘符路径 `C:\x`（或 `C:/x`）解析为 `/mnt/c/x`；原生 Windows 宿主上
  `/mnt/c/…` 或 `/c/…` 解析为 `C:\…`（该盘不存在时就是 `missing`）。UNC 在 WSL 里没有可靠映射，因此是 `foreign`。
  翻译不靠词法信任——翻译后的路径仍必须能真实解析。
- **foreign 条目保持 inactive**：当前宿主无法表达的写法（macOS/Linux 上的 Windows 路径、Windows 上无法映射的
  POSIX 路径）变为 **inactive + 告警**，配置照常保存，因此同一份文档可以在多台机器上共用（dotfiles、共享的
  设置仓库），不需要为每台机器写一份。
- **保存时校验**：文件系统/卷根（`/`、`C:`、`C:\`、UNC 共享根）、盘符相对写法、重复路径（Windows 上大小写不敏感）
  会被拒绝。翻译之后才成为卷根的写法（WSL 的 `/mnt/c`）显示为 `[已拒绝]` 并在解析时忽略。

## 设置页：一个纯文本编辑器，一个保存按钮

整页就是**一个编辑全部规则的纯文本编辑器**——没有行列表、没有模式切换，只有一个 **保存** 按钮。每行
`路径 | 访问级别 | 作用面`；编辑器总是渲染完整三段，不带分隔符的裸名（`.git`、`.env`）是名称规则。手写的
`#` 注释与空行会被忽略。

- **省略字段时的默认值**：编辑器上方会显示当前生效的默认值——访问级别取 `defaultAccess`（默认 **write**，即
  会话为 workspace-write 时可写），作用面取 `defaultSurfaces`（默认 **fs+shell**）；两者可在配置文档的
  `extra-paths` 段里修改。
- **内置示例**：编辑器上方有可展开的「示例与支持的写法」，列出常用形式（访问级别、作用面、名称规则、模式、
  Windows/WSL 路径），并同样写明默认值。
- **基准工作区**只用于预览与宿主侧解析，不属于保存的配置内容。
- **长行不换行**：编辑器（以及预览里的路径）不会自动折行——长路径/模式保持原样，用触控板/鼠标横向滚动查看，
  避免断行后难以核对。
- **保存** 一步解析整段文本（全有或全无）并写入结构化的 `paths` 数组；解析错误按行号提示、不保存任何内容。
  宿主拒绝写入（命名空间被 home/CLI 覆盖）时会明确显示原因，不会假装保存成功。
- **解析预览**按草稿给出答案：生效可写根、只读根、被禁止的根、逐条状态（`[生效]`、`[缺失]`、`[已拒绝]`、
  `[当前平台不适用]`）与告警；默认折叠成一行。
- 行/模式/名称规则的细节现在都在文本里，预览展示解析结果——不再有第二个需要同步的编辑器。

## 已知边界

- **shell 侧的 `deny`/`read` 仅在 macOS（seatbelt）与 Linux bwrap 下可靠。** Linux landlock 是纯 allow-list——
  只能加不能减（没有 bwrap 的 WSL 安装会落到这里）；Windows ACL runner 会拒绝不认识的参数。这些平台上 bash
  不遵守 `deny`/`read`：插件不会硬塞参数，而是按「方言 + 规则集」只告警一次，页面显示能力横幅。fs 工具始终执行规则。
- **裸名规则只保护 fs 工具，不保护 bash。** `.git`、`.env`、`node_modules` 由 `read`/`write`/`edit`/apply-patch
  等工具与 `grep`/`glob` 参数守卫按词法实时匹配；`bash` 仍可读写它们——沙箱 profile 只能写具体路径，而"按命令枚举"
  方案（成本、滞后、部分覆盖）已被否决。要让 shell 也受约束，请改用路径模式，例如 `**/.git`（锚定当前会话
  工作区）或 `<工作根>/**/.git`；在能扣减权限的平台上，模式在 fs/shell 两侧都精确。
- **`grep`/`glob` 绕过 `ctx.fs`**：宿主直接运行打包的 ripgrep。插件的工具层守卫会可靠拒绝**显式 `path` 参数**
  命中被禁路径的 `grep`/`glob` 调用，但默认的整个工作区搜索仍可能在结果里带出被禁子目录。敏感数据请放在工作区
  之外并 deny——在 shell 能扣减权限的平台上，bash 也会被拦。
- **元数据不拦截**：`stat`/`lstat`/`resolve` 等方法只交换元数据，因此被禁路径的存在性、大小与身份仍可能被观察到；
  内容读取、目录列举与 `watch` 会被拒绝。
- **代理之外的消费者**：经 `ctx.get('fs')` 直接拿文件系统的服务、LSP/MCP 子进程、以及在加载期缓存了 `ctx.fs`
  的宿主服务，不受代理约束。
- **Windows 的 shell 侧授权仍不受宿主支持**（0.2.2 架构限制）：Windows 上不会为 bash 放行额外路径，0.3.0 不改变
  这一点。fs 工具侧照常工作。
- **`danger-full-access` 下**没有 shell 沙箱可注入规则，因此该模式下 shell 侧的 `deny`/`read` 无法执行；fs 工具
  仍按规则拒绝。
- 逐路径的"完全不受限"做不到：bash 沙箱是整次调用粒度。
- 相对路径按会话工作区解析，因此同一份配置在不同工作区指向不同目录——设置页的预览会显示实际解析结果。
- `always-write` 会削弱 `read-only` 急停按钮对该路径的作用。
- 写在工作区外的文件不会出现在 `deliverables` 的工作区变更卡片里。
